# 04 — Repository Structure and Conventions (Tech Lead hat)

**TL;DR**
1. The target tree is designed from scratch: `apps/{api,web,mobile,site}` and `packages/{domain,contracts,ai,api-client}` in a pnpm workspace.
2. The prototype is moved to `legacy/prototype/` in the first story, used as reference while its good parts are ported, and deleted at the end of R1.
3. Section 3 maps every existing file to its new home or to deletion, with the story that does it.
4. Rules are enforced by tools, not by hope: strict TypeScript, ESLint, dependency-cruiser, tests on the real runtime, commit linting.
5. CI runs eleven stages with the exact commands in section 12; `main` deploys to production automatically.

## 2. Monorepo decision

pnpm workspaces without a task runner (ADR-0010). Internal packages export TypeScript source. The only commands stories use are the root scripts:

| Script | Runs |
|---|---|
| `pnpm dev` | `wrangler dev` (port 8787) and `vite` (port 5173) in parallel |
| `pnpm lint` | `eslint .` |
| `pnpm format` / `pnpm format:check` | `prettier --write .` / `prettier --check .` |
| `pnpm typecheck` | `pnpm -r typecheck` (`tsc --noEmit` in each package) |
| `pnpm test` | `pnpm -r test` (`vitest run` in each package) |
| `pnpm depcruise` | `depcruise apps packages --config .dependency-cruiser.cjs` |
| `pnpm build` | `pnpm --filter @slj/web build && pnpm --filter @slj/api build` (`vite build`, then `wrangler deploy --dry-run --outdir dist`) |
| `pnpm e2e` | `pnpm --filter @slj/web e2e` (Playwright) |
| `pnpm evals` | `pnpm --filter @slj/ai evals` (from S-R1-062) |
| `pnpm size` | `pnpm --filter @slj/web size` (from S-R1-091) |

Package-level scripts in `apps/api`: `dev`, `build`, `typecheck`, `test`, `types` (`wrangler types`), `db:generate` (`drizzle-kit generate`), `db:migrate:local` (`wrangler d1 migrations apply slj-local --local`), `seed:dev` (from S-R1-092).

## 5. Layering: where each concern lives

| Concern | Lives in | May use |
|---|---|---|
| **Domain** — rules, calculations, value objects | `packages/domain` | `zod` only; no I/O, no clock, no randomness |
| **Contracts** — shapes crossing the wire | `packages/contracts` | `@slj/domain`, `zod` |
| **Application** — use cases, orchestration of repositories and events | `apps/api/src/modules/*/*-service.ts` | `@slj/domain`, `@slj/contracts`, `@slj/ai` types, own and other modules' services, ports |
| **Ports** — what the application needs from outside | `apps/api/src/modules/*/ports.ts`, `packages/ai/src/tools/ports.ts` | types only |
| **Infrastructure** — database, auth, HTTP clients, sinks | `apps/api/src/infra` | anything; implements ports |
| **Interface** — HTTP routes and middleware | `apps/api/src/http` | services from the container, contracts |
| **Composition** — wiring | `apps/api/src/composition/container.ts` | everything |
| **AI** — router, agents, tools, guardrails, providers | `packages/ai` | `@slj/domain`, `@slj/contracts` |
| **Presentation** — screens and components | `apps/web/src/screens`, `apps/web/src/ui` | hooks, `@slj/domain` (pure functions), `@slj/contracts` (types) |

A route handler does four things only: read validated input, call one service method, map the result to the response contract, return. Business rules in a route are a review failure.

## 6. Error-handling and logging conventions

**Errors**
- Services throw subclasses of `AppError` from `apps/api/src/shared/errors.ts`: `ValidationError`, `UnauthenticatedError`, `ForbiddenError`, `NotFoundError`, `ConflictError`, `OnboardingRequiredError`, `RateLimitedError`, `UpstreamUnavailableError`. Codes and HTTP statuses are in `03_ARCHITECTURE.md` §11.
- Never `throw new Error("…")` for an expected condition, and never return `null` to mean "failed".
- `packages/domain` functions do not throw for invalid business input; they return a typed result or are called with already-validated input.
- Only `error-handler.ts` formats error responses. Only it, the outbox dispatcher and the AI decorators call Sentry.
- The client maps `ErrorCode` to a translated message in `errors.json`; server `message` text is for logs, not for display.
- `catch` blocks must rethrow, map to an `AppError`, or handle with a comment saying why swallowing is safe.

**Logging**
- One JSON line per event through `logger` in `apps/api/src/shared/logger.ts`: `{ level, event, requestId, route?, status?, durationMs?, userRef?, … }`. `userRef` is the hashed analytics ID.
- Levels: `debug` (dev only), `info` (request completed, job done), `warn` (fallback used, limit hit), `error` (5xx, failed job).
- Never log request or response bodies, emails, names, addresses, tokens, message text or prompt text.
- `console.*` is forbidden outside `logger.ts` (ESLint `no-console`).

## 7. Commit, branch and pull-request conventions

- **Branch:** `<type>/S-R1-018-tasks-api` from `main`. One story per branch.
- **Commit:** Conventional Commits. Types `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `ci`, `build`, `perf`. Scopes `api`, `web`, `domain`, `contracts`, `ai`, `client`, `mobile`, `site`, `repo`. The subject ends with the story ID: `feat(api): add tasks API (S-R1-018)`. Enforced by commitlint (S-R0-033).
- **Pull request:** title equals the commit subject; body is the template (story link, what changed, how verified with pasted command output, checklist from the story's Definition of Done). Squash merge. `main` is protected: CI must pass.
- **Story status:** the executor sets `**Status:**` in the story file to `IN PROGRESS` on the first commit and `DONE` in the final commit, and updates `12_BACKLOG_INDEX.md`. `docs/BOARD.md` is updated when a release or epic changes state.
- **History:** no force-push to `main`, no rewritten history, no merge commits on `main`.

## 9. Definition of Ready and Definition of Done

**Ready** — a story may start when:
1. Every story in its `Depends on` list is `DONE`.
2. Its "Files to read first" exist at the stated paths.
3. Any HUMAN chore it needs (keys, accounts) is done or the story states the fallback.
4. No decision is left to the executor; if one appears, the story is `BLOCKED` and the planner fixes the story or an ADR.

**Done** — a story is done when:
1. `pnpm format:check && pnpm lint && pnpm typecheck && pnpm depcruise && pnpm test` pass locally and in CI.
2. Every acceptance criterion is demonstrated by a test or by pasted output of the story's verification commands.
3. No new `any`, no `@ts-ignore`, no `eslint-disable` without a linked story ID, no `TODO` without a story ID.
4. New user-facing strings are in the i18n files; new events are in the taxonomy; new env vars are in `.dev.vars.example` and ADR-0024's table.
5. The safety rules of spec §23 are not weakened; AI-touching stories run `pnpm evals`.
6. Documentation that the story names is updated; the story file's status is `DONE`.
7. The change is one squash-merged commit on `main` and, for deployable changes, production health is green.
