# ADR-0006 — Session and token model

**TL;DR**
1. A session is an opaque random token stored in the `session` table; there are no JWT access or refresh tokens.
2. Web and desktop PWA carry it in an httpOnly, Secure, SameSite=Lax cookie on the API's own origin.
3. Native shells carry the same token as `Authorization: Bearer`, kept in the OS keychain/keystore.
4. Revocation is immediate: deleting the row signs the device out; "sign out everywhere" deletes all rows for the user.
5. Reversal cost S; runner-up is a short-lived JWT with a rotating refresh token.

|---|---|
| Status | Accepted (2026-11-14) |

## Context

The web app and API share one origin (ADR-0009), so first-party cookies work without CORS. Capacitor shells load the app from `capacitor://localhost` (iOS) or `https://localhost` (Android); from there the API is cross-site, and WebKit blocks third-party cookies. The prototype's stateless JWT cannot be revoked and falls back to a known default secret.

## Decision drivers

1. Immediate revocation (weight 3).
2. Works both same-origin (web) and cross-origin (shells) (weight 3).
3. Simple enough for weak models to implement correctly (weight 3).
4. Exposure to XSS and CSRF (weight 2).
5. Per-request overhead (weight 1).

## Options

Scores 1–5; maximum weighted total 60.

| Option | Revocation | Web + shells | Simplicity | XSS/CSRF | Overhead | Total |
|---|---|---|---|---|---|---|
| A. Keep the stateless 30-day JWT cookie (do nothing) | 1 | 2 | 4 | 3 | 5 | 32 |
| **B. Opaque DB session: cookie on web, Bearer in shells** | 5 | 5 | 4 | 4 | 3 | **53** |
| C. Short-lived JWT access token + rotating refresh token | 3 | 5 | 2 | 3 | 4 | 40 |
| D. Vendor-issued JWT verified statelessly (Firebase, Clerk) | 2 | 5 | 3 | 3 | 5 | 41 |

## Decision

| Aspect | Rule |
|---|---|
| Token | Opaque, generated by Better Auth, stored in `session.token` |
| Lifetime | `expiresIn` 30 days; `updateAge` 1 day (sliding) |
| Web / desktop PWA transport | Cookie set by Better Auth: httpOnly, Secure (off only on `http://localhost`), SameSite=Lax, path `/` |
| Native transport | Better Auth `bearer()` plugin. After sign-in the client reads the `set-auth-token` response header, stores the value with `@aparajita/capacitor-secure-storage`, and sends `Authorization: Bearer <token>` on every request |
| Server check | `SessionResolver.resolve(headers)` → `auth.api.getSession({ headers })`; one indexed D1 read per request |
| Cookie cache | Off at rung 0, so revocation is instant. Turn on (`maxAge` 300 s) only when D1 reads per day pass 2.5 million |
| CSRF | SameSite=Lax; Hono `csrf()` origin check on every non-GET `/api/v1/*` request that carries a cookie; Better Auth `trustedOrigins` for `/api/auth/*`. Requests authenticated by Bearer skip the origin check because no ambient credential is sent |
| XSS | Token is never readable by page script on web (httpOnly). Content Security Policy from S-R0-035. In shells the token lives in secure storage, not `localStorage` |
| CORS | Web: none needed. Shells: allow-list of `capacitor://localhost`, `https://localhost`, `http://localhost` with `Authorization` and `Content-Type` headers, `credentials: false` (S-R2-044) |
| Sign out | `authClient.signOut()` deletes the current session row and clears the cookie or stored token |
| Sign out everywhere | `authClient.revokeSessions()`; offered in Settings (S-R2-020) |
| Sensitive actions | Account deletion and data export require a session younger than 24 hours (`freshAge`); otherwise the user signs in again |
| Storage on device | On sign-out the client clears the persisted query cache and the mutation outbox (ADR-0014) |

## Consequences

**Good:** one mental model for all platforms; no refresh logic; compromise of the database-stored token is bounded by row deletion.

**Bad:** every authenticated request reads D1 once; a stolen Bearer token is usable until it expires or is revoked (mitigated by secure storage and device-level sign-out).

**Neutral:** a future first-party desktop shell (Tauri) uses the same Bearer path.

## Reversal cost

**S.** The session mechanism is hidden behind `SessionResolver` and the API client's `getAuthHeaders()`.

## Flip trigger

Move to option C if a second backend service must authenticate users without access to the session table, or if session reads exceed 20% of D1 rows read at rung 2.
