## 1. Why
A web page in a WebView feels like a web page unless the edges are right: icon, splash, status bar, safe areas, the Android back button, the keyboard. App Review guideline 4.2 ("minimum functionality") is also easier to pass when the app behaves natively (ADR-0015 "Bad" consequences).

## 3. Design notes
- Icons and splash: generated by `@capacitor/assets` from the files in `apps/mobile/assets/`. Icon = the S-R2-001 mark on ground `#f2f5f4`; Android adaptive icon background `#f2f5f4`. Splash = the mark centred, ground `#f2f5f4` (light) and the dark ground token (dark). No text on the splash.
- `capacitor.config.ts` additions: `plugins: { SplashScreen: { launchAutoHide: false, backgroundColor: "#f2f5f4" }, Keyboard: { resize: "native" } }`, `backgroundColor: "#f2f5f4"`.
- `platform/chrome.ts`:

```ts
export function initNativeChrome(theme: "light" | "dark"): Promise<void>;   // native only: status bar style + background, then SplashScreen.hide()
export function setStatusBarTheme(theme: "light" | "dark"): Promise<void>;
export function registerBackButton(handlers: { canGoBack(): boolean; goBack(): void; closeOverlay(): boolean }): () => void;
```

- Splash: hidden by `initNativeChrome` after the first route has rendered (called from an effect in `app-shell.tsx`), with a 3-second safety timeout so a crash never leaves the splash up.
- Status bar: light theme → dark icons on ground; dark theme → light icons on the dark ground; updated when the theme switcher changes.
- Safe areas: `index.html` viewport gains `viewport-fit=cover`; `base.css` sets `padding-top: env(safe-area-inset-top)` on the app header and `padding-bottom: env(safe-area-inset-bottom)` on the tab bar and on bottom-fixed bars (install bar, offline indicator, toasts). These rules are harmless on the web.
- Android back button (`App.addListener("backButton")`), in order: an open dialog or sheet → close it (`closeOverlay` returns true); history can go back → go back; on a root tab → `App.minimizeApp()` (never exit silently in the middle of a form: when a form is dirty, the existing unsaved-changes dialog shows first).
- Web feel removed on native (CSS under `html[data-native]`, set at boot when `isNative()`): `-webkit-touch-callout: none`, `-webkit-tap-highlight-color: transparent`, `overscroll-behavior: none` on the root, `user-select: none` on navigation chrome only (text in content stays selectable). Text inputs keep 16 px font size so iOS does not zoom.
- Keyboard: with `resize: "native"` the WebView shrinks; the concierge composer and form submit buttons must stay visible — check the three forms (onboarding, housing, concierge).
- External links (`target="_blank"`, legal pages, partner links) open in the system browser through `platform/links.ts` `openExternal(url)` (`@capacitor/browser` is **not** added; use `window.open(url, "_system")` behaviour provided by Capacitor's default navigation handling and verify on both platforms).
- Rotation is allowed; the layout already adapts by width.

## 5. Acceptance criteria
- AC1: Given a cold start on both platforms, then the splash shows the mark on the ground colour and disappears when the first screen is ready, with no white flash.
- AC2: Given a notched iPhone, then no content sits under the status bar or the home indicator, and the tab bar targets remain at least 44 px high above the indicator.
- AC3: Given the Android back button, then it closes an open dialog first, then goes back in history, then minimises the app from a root tab.
- AC4: Given the theme switched to dark, then the status bar icons are readable.
- AC5 (negative): Given the splash and a boot failure (throw in the first route), then the splash is hidden within 3 seconds and the error screen is visible.
- AC6 (negative): Given the web build, then `initNativeChrome` is never called and the web layout is pixel-identical in the Playwright visual check of the dashboard.
